Fast multipart/form-data parsing for Python

A streaming parser written in Rust and a drop-in replacement for multipart: the same API, the same semantics, and faster on every input, including adversarial ones.

Usage

The package installs as kirimi-multipart and is imported as kirimi. Code written for multipart works after changing the import.

from kirimi import parse_form_data

forms, files = parse_form_data(environ)
name = forms.get("name")                # str
upload = files.get("upload")            # MultipartPart
if upload is not None:
    upload.save_as("/srv/uploads/upload.bin")

Parse a WSGI request into form fields and file uploads.

from kirimi import MultipartParser

for part in MultipartParser(stream, boundary, content_length):
    print(part.name, part.filename, part.size, part.is_buffered())

Parse a stream part by part. Small parts stay in memory, large ones are spooled to temporary files.

from kirimi import MultipartSegment, PushMultipartParser

with PushMultipartParser(boundary) as parser:
    while not parser.closed:
        for event in parser.parse(read(65536)):
            if isinstance(event, MultipartSegment):
                ...  # start of a part: event.name, event.filename, event.headerlist
            elif event:
                ...  # chunk of the part body (bytes)
            else:
                ...  # end of the part

Drive the non-blocking parser yourself, for example in an async server. parse_blocking() and parse_async() wrap this loop for blocking and async read functions.

See the multipart documentation for the full API.

Differences from multipart

kirimi matches multipart's public API. Where behaviour differs, it is to make results independent of how the input is chunked, or to follow the RFC.

Chunking-independent results

  • A bare LF in a part header line is always an error.
  • A first boundary that does not follow a CRLF is always an error.
  • A header line of exactly max_header_size bytes is accepted.

Other

  • Boundaries containing CR are rejected (RFC 2046).
  • header_charset supports UTF-8, Latin-1 and ASCII only; non-ASCII header names are rejected.
  • parse() returns a list of events and raises before returning any events of a failing chunk.
  • MultipartParser and MultipartPart are Rust types without the private attributes.

Details are in the README.
